# MuJoCo 控制层重构设计

## 目标

在不改变当前 MuJoCo 仿真控制参数、符号约定、执行器顺序和启动方式的前提下，整理控制层职责，彻底删除 `LOCK_LEG_BODY_ANGLE_ZERO` 腿身角锁定功能，并将 Python 源码中的注释和文档字符串统一为中文。

## 范围

- 删除 `Simulation.py` 中的 `LOCK_LEG_BODY_ANGLE_ZERO` 开关、`LEG_BODY_ANGLE_KP`、`LEG_BODY_ANGLE_KD` 以及对应的 `apply_lqr` 分支。
- 保留 `FORCE_LQR_THETA_ZERO`，它是独立的 LQR 诊断开关，不属于腿身角锁定功能。
- 将滚转 PID、腿长 PID、分腿抑制、LQR 状态/符号映射和 VMC 力矩映射拆分为职责清晰的函数，集中放入 `Controller.py`。
- 让 `Simulation.py` 只负责仿真入口、传感器更新调用和控制流程编排。
- 翻译所有 Python 文件中的英文注释、文档字符串和面向维护者的说明；删除注释掉的旧代码、未使用导入及无意义空白。
- 不修改 MJCF 几何、质量、执行器限幅、LQR 增益文件或控制数值参数。

## 架构

`Simulation.py` 保留 `main()` 和对外使用的 `apply_lqr()` 入口。`apply_lqr()` 按固定顺序调用控制器函数：更新 VMC 几何状态、计算左右腿 LQR 输出、计算分腿修正、计算腿长和滚转径向力、映射到 VMC 关节力矩、写入执行器。每个步骤通过明确的参数和返回值连接，不依赖新的全局状态。

`Controller.py` 承载纯控制逻辑和已有 PID 类，提供可单独测试的函数。积分状态继续保存在调用方传入的 VMC 或机器人对象上，以保持现有跨控制周期行为；禁用控制时清零积分。VMC 的几何和雅可比计算继续留在 `VMC.py`，传感器读取和执行器限幅继续留在 `environment.py`。

## 数据流和行为约束

1. `LegWheelRobot.sensor_read_data()` 更新姿态、角速度、轮速、底盘位置和四个关节角。
2. 控制器用左右关节角和镜像后的俯仰/陀螺仪输入更新两个 `leg_VMC` 实例。
3. LQR 分别计算轮端 `T` 与虚拟髋关节 `Tp`，维持当前左右腿状态镜像和 MATLAB `K @ state` 约定。
4. 分腿 PID 对两腿 `Tp` 施加相反修正；腿长 PID 生成径向 `F0`；滚转 PID 生成左右腿差分 `F0`。
5. VMC 雅可比将 `F0`/`Tp` 转换为四个关节力矩，按现有 XML 执行器顺序写入；最终限幅仍由 `environment.py` 执行。
6. 删除锁定分支后，`Tp` 始终来自 LQR 输出并叠加分腿 PID 修正，不再覆盖为腿身角局部 PD 输出。

## 错误处理

保留当前错误语义：增益表缺失、LQR 状态非有限、MuJoCo 模型加载失败和几何计算异常继续直接抛出。重构函数不捕获这些异常，也不静默替换控制输出。已有的积分限幅、输出限幅和禁用时复位行为必须保持不变。

## 测试策略

- 新建标准库 `unittest` 测试，覆盖提取后的滚转 PID、腿长 PID、分腿 PID、LQR 状态映射和执行器力矩映射的关键行为。
- 增加结构回归测试，确认源码不再包含 `LOCK_LEG_BODY_ANGLE_ZERO`、`LEG_BODY_ANGLE_KP` 或 `LEG_BODY_ANGLE_KD`。
- 测试不启动 MuJoCo viewer；对需要机器人状态的函数使用最小真实数据对象，避免验证被图形环境阻塞。
- 按 TDD 执行：先写一个断言锁定功能标识和分支不存在的失败测试，确认失败原因是旧代码仍存在；再实施最小重构，运行新增测试和全量测试；最后只做保持测试绿色的整理。

## 完成标准

- 所有锁定腿身角相关标识与代码路径全部删除，正常 LQR + 分腿控制路径可执行。
- 所有被维护的 Python 注释和文档字符串为中文，且没有注释掉的旧实现或明确未使用导入。
- `unittest` 测试全部通过，Python 文件可被编译检查，仿真入口仍为 `python Simulation.py`。
- 不改动 MJCF 文件、增益数据或控制参数数值。
